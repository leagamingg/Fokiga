# 资源管理器 (ResourceManager) 高级文档

## 1. 概述

本文档介绍了 FokiGA 项目中资源管理器的高级功能，包括对 AssetBundle 的支持。资源管理器现在可以根据不同的加载策略，灵活地从不同的资源来源加载资源，提高了项目的扩展性和性能。

## 2. 新增功能

### 2.1 资源加载策略

资源管理器现在支持以下三种加载策略：

| 策略 | 描述 | 适用场景 |
|------|------|----------|
| Auto | 自动选择策略，依次尝试 AssetBundle、Resources | 不确定资源来源时使用 |
| Resources | 使用 Resources 文件夹加载 | 小型项目或测试场景 |
| AssetBundle | 使用 AssetBundle 加载 | 中型项目，需要资源分包 |

### 2.2 核心功能增强

- **多策略支持**：同时支持 Resources 和 AssetBundle
- **自动回退**：当一种策略加载失败时，自动尝试其他策略
- **AssetBundle 管理**：内置 AssetBundle 加载和缓存机制
- **统一接口**：保持一致的 API 接口，简化使用
- **异步操作支持**：添加了对 Unity 异步操作的 await 支持

## 3. 架构设计

### 3.1 核心组件

- **ResourceLoadStrategy**：资源加载策略枚举
- **ResourceInfo**：扩展了资源信息，增加了策略和 AssetBundle 信息
- **AssetBundle 缓存**：管理已加载的 AssetBundle
- **多策略加载器**：针对不同策略的加载实现

### 3.2 加载流程

1. **策略选择**：根据指定的策略或默认策略
2. **资源检查**：检查资源是否已加载
3. **策略执行**：根据策略执行相应的加载逻辑
4. **资源记录**：记录资源信息和使用情况
5. **资源返回**：返回加载的资源

## 4. 使用指南

### 4.1 基本使用

```csharp
// 使用默认策略加载资源
var prefab = ResourceManager.Instance.Load<GameObject>("Character/unitychan");

// 使用指定策略加载资源
var prefab = ResourceManager.Instance.Load<GameObject>("Character/unitychan", ResourceLoadStrategy.Resources);

// 异步加载资源
var prefab = await ResourceManager.Instance.LoadAsync<GameObject>("Character/unitychan");

// 异步加载资源（指定策略）
var prefab = await ResourceManager.Instance.LoadAsync<GameObject>("Character/unitychan", ResourceLoadStrategy.AssetBundle);
```

### 4.2 AssetBundle 使用

#### 4.2.1 资源路径格式

对于 AssetBundle 策略，资源路径格式为 `bundleName/assetName`，例如：

```csharp
// 加载 characters AssetBundle 中的 unitychan 预制体
var prefab = ResourceManager.Instance.Load<GameObject>("characters/unitychan", ResourceLoadStrategy.AssetBundle);
```

#### 4.2.2 AssetBundle 构建

1. 在 Unity 中选择资源，设置 AssetBundle 名称
2. 使用 BuildPipeline.BuildAssetBundles 构建 AssetBundle
3. 将构建好的 AssetBundle 文件放在 StreamingAssets 文件夹中

### 4.3 Addressables 使用

#### 4.3.1 配置 Addressables

1. 安装 Addressables 包
2. 配置 Addressables 组和标签
3. 将资源添加到 Addressables 组

#### 4.3.2 加载 Addressables 资源

```csharp
// 使用 Addressables 策略加载资源
var prefab = ResourceManager.Instance.Load<GameObject>("Assets/Resources/Character/unitychan.prefab", ResourceLoadStrategy.Addressables);

// 或使用 Auto 策略，让系统自动尝试 Addressables
var prefab = ResourceManager.Instance.Load<GameObject>("Assets/Resources/Character/unitychan.prefab");
```

### 4.4 模板池使用

模板池功能与之前保持一致，但现在支持从不同来源加载模板：

```csharp
// 预热模板（使用默认策略）
await ResourceManager.Instance.Preload<GameObject>("Character/unitychan", 5);

// 从模板池获取实例
var instance = ResourceManager.Instance.Get<GameObject>("Character/unitychan");

// 归还实例
ResourceManager.Instance.ReturnTemplate(instance);
```

## 5. API 参考

### 5.1 新增 API

#### 5.1.1 ResourceLoadStrategy 枚举

```csharp
public enum ResourceLoadStrategy
{
    Auto,           // 自动选择策略
    Resources,      // 使用 Resources 文件夹
    AssetBundle     // 使用 AssetBundle
}
```

#### 5.1.2 重载方法

| 方法 | 描述 | 参数 | 返回值 |
|------|------|------|--------|
| `Load<T>(string path, ResourceLoadStrategy strategy)` | 同步加载资源（指定策略） | path: 资源路径<br>strategy: 加载策略 | T: 加载的资源 |
| `LoadAsync<T>(string path, ResourceLoadStrategy strategy)` | 异步加载资源（指定策略） | path: 资源路径<br>strategy: 加载策略 | Task<T>: 加载的资源 |

#### 5.1.3 属性

| 属性 | 类型 | 描述 |
|------|------|------|
| `DefaultLoadStrategy` | ResourceLoadStrategy | 默认加载策略 |

### 5.2 现有 API

现有 API 保持不变，但内部实现已更新以支持多策略：

- `Load<T>(string path)`
- `LoadAsync<T>(string path)`
- `Return<T>(T resource)`
- `Unload<T>(T resource)`
- `ClearAll()`
- `GetResourceCount()`
- `Get<T>(string templateName)`
- `ReturnTemplate<T>(T instance)` - 替换了之前的 `Return<T>(T instance)`
- `Preload<T>(string templateName, int count)`
- `Clear()`

## 6. 最佳实践

### 6.1 策略选择

- **小型项目**：使用 Resources 策略，简单直接
- **中型项目**：使用 AssetBundle 策略，平衡性能和复杂度
- **不确定场景**：使用 Auto 策略，让系统自动选择最佳方案

### 6.2 AssetBundle 管理

- **合理分包**：将相关资源放在同一个 AssetBundle 中
- **版本控制**：实现 AssetBundle 版本管理
- **依赖管理**：正确处理 AssetBundle 之间的依赖关系
- **缓存策略**：实现合理的 AssetBundle 缓存策略

### 6.4 性能优化

- **预热资源**：在合适的时机预热常用资源
- **批量加载**：批量加载相关资源，减少加载次数
- **异步加载**：对于大型资源，使用异步加载
- **资源释放**：及时释放不再使用的资源

## 7. 常见问题

### 7.1 AssetBundle 加载失败

**问题**：使用 AssetBundle 策略加载资源失败

**解决方案**：
- 检查 AssetBundle 是否已构建
- 检查 AssetBundle 文件是否在 StreamingAssets 文件夹中
- 检查资源路径格式是否正确（bundleName/assetName）
- 检查 AssetBundle 是否包含指定的资源

### 7.2 资源冲突

**问题**：不同策略加载的资源冲突

**解决方案**：
- 为不同来源的资源使用不同的路径
- 明确指定加载策略，避免 Auto 策略的自动选择
- 合理管理资源的生命周期

## 8. 扩展与定制

### 8.1 自定义加载策略

```csharp
public class CustomResourceManager : ResourceManager
{
    protected override void OnAwake()
    {
        base.OnAwake();
        // 自定义初始化逻辑
    }
    
    public override T Load<T>(string path, ResourceLoadStrategy strategy)
    {
        // 自定义加载逻辑
        return base.Load<T>(path, strategy);
    }
}
```

### 8.2 自定义 AssetBundle 加载

```csharp
public class CustomResourceManager : ResourceManager
{
    private AssetBundle LoadAssetBundle(string bundleName)
    {
        // 自定义 AssetBundle 加载逻辑
        // 例如从服务器下载 AssetBundle
        return base.LoadAssetBundle(bundleName);
    }
}
```

## 10. 总结

资源管理器的高级版本通过支持多种资源加载策略，为 FokiGA 项目提供了更加灵活和强大的资源管理能力。它不仅保持了原有的功能，还增加了对 AssetBundle 的支持，使得项目可以根据不同的规模和需求选择合适的资源管理方案。

通过合理使用资源管理器的高级功能，可以显著提高游戏的性能和稳定性，减少内存占用，实现更加灵活的资源管理策略。

此外，资源管理器还添加了对 Unity 异步操作的 await 支持，使得异步加载代码更加简洁易读，提高了开发效率。
